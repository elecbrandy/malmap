# 백엔드 (backend/)

최상위 `AGENTS.md`의 전역 규칙을 먼저 따른다. 아래는 이 영역의 추가 규칙.

## 성격

작고 빠른 API 서버. 하는 일은 세 가지뿐: 오늘의 지도 데이터 제공, 검색어 채점, 진행 기록. 인증/결제/실시간/마이크로서비스는 없다 — 추측으로 미리 만들지 않는다.

ORM은 필수가 아니다. 쿼리가 적고 대부분 pgvector 연산이라 `psycopg` 직접 쿼리가 더 단순할 수 있다. 사용자와 정하되 한 방식으로 일관되게(ORM과 raw 쿼리 혼용 금지).

## 핵심 API

**`GET /map`** — `on_map=true` 엔트리들의 word/sense_no/뜻풀이 일부/map_x/map_y 반환. **정답을 역추적할 수 있는 정보(정답 벡터·id·순위)를 응답에 절대 넣지 않는다** — 응답 필드를 하나하나 점검. 하루 고정이므로 캐싱 대상이나, Redis 미리 깔지 말고 앱 메모리에 날짜별로 담는 정도로 시작.

**`POST /guess`** — 흐름:
1. 입력 정규화(앞뒤 공백 제거 정도. 과한 정규화로 다른 단어를 같게 만들지 않음)
2. 그 word의 **모든 sense_no 행을 조회**(동음이의어는 여러 엔트리). 병합하지 않고 각각 따로 채점해 배열 반환 — 이게 이 게임의 특징
3. 각 엔트리와 정답 벡터의 코사인 유사도를 **pgvector `<=>` 연산자로 SQL에서 계산**(파이썬으로 꺼내와 계산 금지). 코사인 유사도 = 1 - 코사인 거리
4. 사전에 없으면 런타임 임베딩 폴백
5. 응답: 엔트리별 `{word, sense_no, definition, similarity, on_map, map_x, map_y}` 배열

**런타임 임베딩 폴백** — 사전에 없는 단어만. 로컬 모델로 벡터 생성 후 `entries`에 캐싱(upsert, `on_map=false` 좌표 없음). **파이프라인과 반드시 동일한 모델**(다른 모델 벡터는 같은 공간에 없어 무의미). 모델 로딩은 앱 시작 시 1회.

**진행 기록** — 익명 세션(UUID)으로 충분(로그인 미리 만들지 않음). `guess_logs`에 추측 기록만. 통계/공유는 나중 마일스톤.

## 채점 주의점

- 정답 판정은 벡터 비교보다 **엔트리 id 일치**로(부동소수점 오차 회피)
- 순위를 보여주려면 일일 정답 확정 시 배치로 전체 순위를 미리 계산해 저장(매 요청 전체 정렬 금지)
- 유사도 원값(-1~1) vs 0~100 가공은 프론트와 합의, 가공 규칙은 한 곳에만

## 하지 말 것

- 정답 역추적 정보를 응답에 넣기
- 동음이의어를 병합해 채점(각각 따로가 핵심)
- 벡터를 파이썬으로 꺼내와 유사도 계산(pgvector `<=>` 사용)
- 파이프라인과 다른 임베딩 모델을 런타임에 사용
- 병목 측정 전 인증/캐시/큐 인프라 도입
